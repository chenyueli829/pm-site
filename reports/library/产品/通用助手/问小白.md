## 一、摘要

- **一句话定位**：北京元石科技推出的中文 **「探索世界的 AI 搭子」**——对话为主轴，叠加 **场景快捷入口**（AI 生图、写作、拍照答疑、学术搜索等）与 **多类型文件拖拽上传**（图片、文档、PPT、表格、文本），强调自研 **问小白 5**、**问小白 o4** 及 **DeepSeek 等模型接入** 的组合叙事。
- **目标用户**：学生与知识工作者、内容创作者、移动端拍照答疑场景用户；依赖 **登录** 保存历史与内容的留存型用户。
- **核心工作流**：选场景或新对话 → 输入或上传文件 → 多轮对话与产出；客户端下载为补充入口。

---

## 二、为何重要

- **场景一键直达**：首页聚合 AI 生图、帮我写作、拍照答疑、学术搜索等入口，把大模型能力拆成 **可点选的高频任务**，降低冷启动与 Prompt 门槛。
- **多模态文件工作流**：支持拖拽图片、文档、PPT、表格、文本等，在 **同一对话** 里解析、摘要与追问，减少多工具打开与复制粘贴。
- **自研型号 + 多模型组合**：以 **问小白 5**、**问小白 o4**（多路并行思考等产品叙事）为品牌锚点，并公开接入 **DeepSeek** 等推理模型，兼顾 **自有技术故事** 与 **能力补位**（榜单类表述需独立验证）。
- **中文「AI 搭子」定位**：话术与功能编排贴近国内学习、写作与搜资料场景，而非抽象「通用聊天」。
- **留存与生态钩子**：**登录** 方可保存内容，配合 **客户端** 拉长使用链路；**投稿智能体赢 VIP** 等运营将 **UGC、会员与增长** 串在同一产品内（规则以官方为准）。

## 三、目标用户与场景（含痛点）

### 场景与痛点对照

| 用户场景 | 旧流程痛点 | 产品如何缓解 |
|----------|------------|--------------|
| 写作与文案 | 多工具切换、空白页启动慢 | 「帮我写作」等入口 + 对话迭代 |
| 学习与搜资料 | 搜索与总结分离、引用零散 | 「学术搜索」+ 对话整合（输出仍需人工核验） |
| 题目 / 实拍答疑 | 题库类 App 与通用 Chat 割裂 | 「拍照答疑」场景入口 |
| 图像需求 | 独立生图产品与对话分离 | 「AI 生图」（官网标「限量免费」） |
| 长文档 / 混合格式 | 多处打开、复制粘贴 | 拖拽上传多类型文件，统一解析对话 |

## 九、差异化与护城河

- **差异化**：中文场景入口聚合；元石 **自研模型 + DeepSeek 等接入** 的组合；国内合规与分发语境。
- **护城河**：模型与数据飞轮、工程体验、用户习惯；技术侧公开 **论文、Deep Research Bench** 等背书（见元石官网）。若 API 与开发者生态未做强，壁垒更依赖 **C 端体验与迭代速度** 而非单一聊天 UI。
- **风险**：与国内头部助手同质化；上传文档的 **隐私与合规** 需在用户协议中自行核对；未登录摩擦与会员策略影响转化。

## 十三、Product Q&A

| 问题 | 回答 |
|------|------|
| **用户第一次为什么来？** | 需要中文多合一 AI：聊、传文件、写、学术、拍题、生图，入口明确。 |
| **用户第二次为什么回来？** | 登录后内容可保存；重复文档/写作/学习场景。 |
| **解决了旧工作流中哪些痛点？** | 减少多工具切换；多格式文件统一解析入口。 |
| **核心护城河是什么？** | 模型迭代 + 体验 + 习惯；技术叙事与评测背书辅助信任。 |
| **聊天工具 vs 任务完成工具？** | **混合型**：对话为底，UI 明显偏向任务场景与文件任务。 |
| **AI 是主角还是嵌入工作流？** | 品牌上问小白 5 / o4 是明星；交互上用上传区与场景键嵌入任务。 |
| **产出可编辑/可验证/可分享/可复用？** | 文本可复制编辑；事实类须用户核验；保存依赖账号体系。 |
| **变现靠模型能力还是工作流价值？** | 从可见信息看偏 **会员/VIP、限量权益、活动**；是否按 API/token 对开发者收费待查。 |
