# Consensus — 深度研究

**品类**：搜索与研究 · 学术与循证检索 · **最后更新**：2026-04-09

- 官网：https://consensus.app
- 操作文档 / 帮助：`to verify`（以站内 Help / 文档区为准）
- 体验入口：以官网注册 / 机构开通为准（部分高校图书馆提供机构访问，具体名单与期限以各校说明为准）

---

## 一、摘要

| 字段 | 内容 |
|------|------|
| 一句话介绍 | Consensus 团队推出的面向科研与专业写作的 **AI 学术检索与证据汇总** 类产品（约 2020 年代起持续迭代，具体首版节点 `to verify`），在**大规模同行评审文献语料**上做语义搜索，将「多篇论文如何回答同一问题」整理为**可核对、可导出引用**的结构化视图。 |
| 目标用户 | 研究生、高校教师、临床与卫生政策相关从业者、需要循证支撑的产业研究/咨询、科技报道者。 |
| 核心工作流 | 提出可检验的研究问题 → 检索与筛选论文 → 查看支持/反对/不确定等证据向汇总（如 Consensus Meter）→ 深入单篇 Snapshot → 导出参考文献格式。 |

**语料与合规叙事（摘要补充）**：官网曾宣称 **2.5 亿+** 篇量级文献池及与出版方合作的**授权全文**等（以官方最新表述为准）。

---

## 二、为何重要

Consensus 处在 **「学术数据库 × 生成式摘要 × 循证决策」** 的交叉点：不是替代 PubMed/Semantic Scholar 的**原始检索 UI**，而是把「读完 50 篇摘要再画趋势」压缩成**结构化证据视图**。

**对 PM 的价值**：研究 **封闭/半封闭学术语料** 上如何做 **可解释聚合**（多少篇支持、研究设计类型、年代分布），以及 **B2C 订阅 + B2B2C 图书馆** 双通道分发。

## 三、目标用户与使用场景

### 3.1 用户类型

| 类型 | 特征与需求 |
|------|------------|
| 研究生与青年学者 | 综述、开题、方法对齐；时间紧、需可引用证据链 |
| 临床与政策相关 | 高利害决策前快览证据版图；须回原文核验 |
| 产业与咨询 | 客户报告需文献背书；批量导出与一致性 |
| 教学者 | 引导学生构造可检验问题（PICO 等） |

### 3.2 高频场景（场景—痛点—缓解）

| 用户场景 | 旧流程痛点 | 产品如何缓解 |
|----------|------------|--------------|
| 系统性文献综述 | 关键词组合试错、漏检与偏倚 | 自然语言问题 + 语义检索 + 筛选维度 |
| 临床/政策快览 | 没时间逐篇读方法学部分 | Snapshot、研究设计标签（如 RCT、荟萃分析等，以产品为准） |
| 写作与投稿 | 手工整理引用格式 | 多格式导出，减少格式工 |
| 教学 | 学生不会构造可答的 PICO 式问题 | 引导把问题改写成文献可检验形式（依赖用户教育） |

## 四、核心工作流与交互模型

### 4.1 心智模型

**问题驱动**：从「研究问题」出发，而非仅从关键词出发。

### 4.2 证据聚合与分层能力

强调**多篇论文对同一命题的态度分布**，降低「单篇摘要幻觉式代表全场」的风险（用户仍需读原文做高利害决策）。**深度检索**：Pro / Deep 等层级（名称以定价页为准）通常对应更强分析、更大语料或批量能力。

### 4.3 局限

生成层仍可能误读统计或外推；覆盖偏见与授权范围因刊与协议而异（见第十一节）。

## 五、核心产品功能

### 5.1 模块与入口

| 模块 / 能力面 | 用户价值 | 主要入口或路径 |
|---------------|----------|----------------|
| 语义检索与筛选 | 从自然语言问题到论文集合 | 主搜索 / 问题框 |
| 证据向汇总 / Meter | 支持、反对、不确定等分布 | 结果页可视化区 |
| Snapshot / 单篇深入 | 方法与设计标签快览 | 单篇卡片 |
| 导出与引用 | 写作与投稿效率 | 导出菜单 |
| 订阅与机构 | 额度、深度能力、合规获客 | 定价页、图书馆通道 |

### 5.2 边界

强项在**同行评审语料上的可解释聚合**；不替代阅读原文与高利害决策责任；开放网页与实时新闻非主战场（对照 **Perplexity** 等）。

### 5.3 套餐与版本

免费额度 + Pro 等分层；**具体价格与功能名以 https://consensus.app 为准**（`to verify`）。

## 六、关键技术分析

**整体结论**：向量检索与元数据过滤打底，生成层聚焦**可追溯陈述**与**研究质量差异**的呈现，产品壁垒在**语料授权、聚合 UX 与机构渠道**的组合，而非单一模型。

### 6.1 架构

- 向量检索 + 元数据过滤 → **可筛选的论文列表**。
- 摘要与结构化抽取 → **Study Snapshot、证据表、Consensus 可视化**。

### 6.2 难点与突破

| 难点 | 现状或方向 |
|------|------------|
| 幻觉与过度概括 | UI 强调回到具体论文；用户教育成本高 |
| 出版商授权与全文可用性 | 因刊与协议而异，需持续运营 |
| 覆盖偏见 | 英文与高分期刊主导场景下的代表性风险 |

### 6.3 壁垒

授权文献池规模、机构背书与 B2B2C 分发、证据视图产品化经验。

---

## 七、首次使用与重复使用

### 7.1 首次使用钩子

要写综述、grant、临床指南背景，需快速扫证据版图；机构或图书馆入口降低试用摩擦。

### 7.2 重复使用理由

机构许可、引用导出、问题历史与团队工作流（若有）；比「自己读完 50 篇摘要」的时间节省可感知。

### 7.3 留存弱点

若个人用户感知「年费 > 节省时间」则易流失；高利害场景仍常回免费数据库核对。

## 八、痛点与缺口

### 8.1 已解决

见第三节场景表及第十三节 Q&A；核心是将**多文献态度分布**产品化，并支持导出。

### 8.2 未解决或部分解决

误读统计显著性、外推结论；社会科学与小语种覆盖；全文可用性碎片；对 **Elicit、Scite、Scholar** 等的差异化需随版本更新核对（见第十四节）。

---

## 九、差异化与护城河

### 9.1 关键差异化

**「多少篇论文持何观点」** 的可审计叙事 + 学术语料索引边界 + 机构渠道。

### 9.2 护城河

语料与合作网络、图书馆关系、产品在循证工作流中的占位。

### 9.3 风险压力

通用答案引擎加强学术模式；开源与竞品在文献发现、引用网络上的并行创新。

## 十、商业模式与增长

- **订阅**：分层能力（免费额度 + Pro 等），**具体价格以官网定价区为准**。
- **机构**：官网宣称 **170+ 大学图书馆**合作与大量专业用户——典型 **B2B2C** 获客与合规背书路径。

---

## 十一、风险、弱点与待验证

- **生成仍可能误读统计显著性或外推结论**：高利害医疗决策必须回原文与方法学。
- **覆盖偏见**：英文、高分期刊、特定领域收录更全时，社会科学或小语种研究可能偏弱。
- **与出版商授权范围**：全文可用性因刊与协议而异，功能描述需随官方更新核对。
- **to verify**：定价档位、企业功能、与 Zotero / EndNote 等生态集成深度。

---

## 十二、PM 启示

### 12.1 PM 启示

- **「多少篇论文持何观点」** 是一种比「一句话总结领域」更**可审计**的产品承诺，适合循证场景。
- 学术产品的增长常靠 **图书馆采购 + 课程嵌入**；C 端订阅要证明**省下的时间 > 年费**。

### 12.2 可关注点

机构续约率、个人付费转化、与出版商条款变更对功能的冲击。

## 十三、Product Q&A

| 问题 | 回答 |
|------|------|
| 什么会促使用户第一次使用？ | 要写综述、grant、临床指南背景，需要快速扫证据版图。 |
| 用户第二次为什么还会回来？ | 机构许可、引用导出、团队工作流（若有）与问题历史。 |
| 旧工作流哪些痛点被解决？ | 关键词试错、手工拼趋势、引用格式工；见第三节表。 |
| 核心护城河？ | 授权语料与机构渠道 + 证据聚合 UX。 |
| 聊天工具还是任务完成工具？ | **任务完成向**：以可检验问题与文献产出为目标，对话为手段之一。 |
| AI 是主角还是嵌入工作流？ | **嵌入循证工作流**；模型服务于检索、抽取与呈现，专业用户仍以论文为真源。 |
| 产出是否可编辑、可验证、可分享、可复用？ | 可导出引用、可回溯单篇；高利害结论须人工回原文**验证**；可分享性依赖导出与协作能力（`to verify`）。 |
| 变现更依赖模型还是工作流价值？ | **偏工作流与语料价值**（订阅 + 机构），模型为组件。 |

## 十四、与竞品的对比

| 对比维度 | 对标 1 | 对标 2 | Consensus 位置 |
|----------|--------|--------|----------------|
| 语料边界 | **Elicit**（文献工作流） | **Perplexity**（开放网 + 学术模式） | 强在同行评审语料上的证据分布视图 |
| 检索入口 | **Semantic Scholar / PubMed** | **Google Scholar** | 少替代原始检索，多替代「读完摘要再手绘趋势」 |
| 证据呈现 | **Scite**（引用声明） | **ResearchRabbit**（发现网络） | 「多篇对一题的态度」聚合与教学/临床快览场景 |
| 与通用答案引擎 | **Perplexity**（学术/Focus） | — | 需 **peer-reviewed 语料与机构合规** 时偏 Consensus；需 **实时新闻与开放网页** 时偏 Perplexity 等 |

*文献数量、合作机构数、定价与功能名以 Consensus 官网为准；高校试用期限以各校图书馆说明为准。*
