# 通用助手 — 品类对比矩阵

**品类定义**：以对话为主要交互的通用 AI 助手，覆盖问答、写作、推理、代码等多场景。

**最后更新**：2025-03-25

---

## 一、核心对比矩阵

| 维度 | ChatGPT | Claude | Gemini |
|------|---------|--------|--------|
| **一句话定位** | 以对话为中枢的「通用智能入口」，正从「聊天」演进到「可编排的智能体平台」 | 面向专业与企业的「高可靠、长上下文」助手，强调可审计输出与严肃工作流 | 嵌入 Google 信息栈的「搜索+生成」一体助手，把 AI 接到用户已有的搜索与办公习惯上 |
| **所属公司** | OpenAI | Anthropic | Google（DeepMind 等联合能力） |
| **目标用户** | 最广谱 C 端 + 开发者 + 企业；从尝鲜到重度生产力用户全覆盖 | 知识工作者、分析师、写作者、合规敏感团队、API 集成方 | 已深度使用 Google 搜索、Gmail、Drive、Workspace 的用户与组织 |
| **核心 Job to be Done** | 「我有一个问题 / 任务，用最短路径得到可用答案或可执行下一步」 | 「我要在复杂材料上做推理、写作、结构化产出，且尽量可控、可迭代」 | 「我要在真实世界信息与协作文档里完成检索、起草、汇总，少切换工具」 |
| **交互模式** | 对话为主；工具调用、插件/GPT、Projects、逐步强化的「任务型」编排 | 对话 + **Artifacts** 等「对话旁的可编辑画布」；长文阅读与多轮修订友好 | 对话 + 与 **Search / Workspace** 的上下文衔接；多模态输入自然融入 Google 产品流 |
| **核心差异化** | **品类定义者与最强心智品牌**；GPT 生态与开发者/API 叙事最成熟；Agent 方向叙事领先 | **安全与可靠心智** + **长上下文** + **可编辑产出（Artifacts）** 形成「严肃工作」闭环 | **分发与嵌入**：搜索入口、Workspace、账号体系带来的**默认可用**与**混合检索增强** |
| **最强场景** | 通用问答、创意与头脑风暴、代码与原型、插件生态下的垂直场景、品牌信任带来的「先试 OpenAI」 | 长文档分析、专业写作与报告结构、需要多轮打磨的可交付草稿、企业向 API 集成 | 需要结合**实时/网页级信息**的任务、在 **Docs/Sheets** 里直接落地、多模态（图/音/视频）与 Google 工具链联动 |
| **最弱环节** | 对「非 OpenAI 栈」办公闭环依赖 copy-paste；免费层能力与政策常随商业策略波动；企业场景需额外产品组合 | 大众心智与 C 端分发弱于 ChatGPT；与微软/Google 级办公套件的原生一体性不如竞品 | 品牌叙事一度碎片化；非 Google 生态用户迁移成本高；「通用助手」独立心智常被视为搜索/办公的附庸 |
| **AI 角色（主角 vs 嵌入）** | **主角型产品**：自身即目的地，用户为 AI 打开独立应用 | **主角型偏专业**：独立站与 API 强，Artifacts 强化「以 AI 为中心的创作台」 | **嵌入型**：AI 常作为搜索、邮箱、文档里的增强层，主叙事是「Google 能力升级」 |
| **产出可编辑/可验证** | 以对话气泡为主，依赖复制粘贴与外部编辑器；Canvas 等能力补强中 | **Artifacts** 支持在界面内结构化编辑、版本感强，利于迭代与「可交付感」 | **原生进 Docs/Sheets** 等，可验证性与协作链条最短，但依赖 Google 文档作为真源 |
| **商业模式** | **Freemium + 订阅（Plus 等）+ API/企业**；生态（GPT Store）延伸变现场景 | **订阅 + API 为企业与集成商核心**；订阅心智清晰，API 驱动 B 端增长 | **与 Google One / Workspace 捆绑**；广告与云生态的协同空间大，单品订阅感知常被「套餐」稀释 |
| **定价** | 分层订阅 + API 按量；C 端价格锚点成熟 | 分层订阅 + API；偏「专业/企业」定价叙事 | 常含在 Google 订阅与 Workspace 档位中；单独 AI 档位因市场与地区而异 |
| **分发优势** | **品牌默认选项**、开发者社区、与 **Microsoft（Copilot 生态）** 的协同曝光、API 无处不在 | 口碑在专业圈层、Hacker/写作社区；**API 与「可信赖模型」** 吸引 B 端 | **Google Search、Android、Workspace、账号体系** 带来的规模化触达与零安装心智 |
| **护城河** | 品牌、用户习惯、开发者与插件生态、多模态与工具链演进速度 | 对齐与安全叙事、长上下文与「专业产出」体验、企业 API 粘性 | 搜索索引与实时数据接口、Workspace 与账户数据飞轮、多模态基础设施与硬件入口（端侧） |
| **PM 研究价值** | 研究「**品类定义 + 平台化**」：如何从聊天扩展到 Agent、商店、企业套件 | 研究「**信任 × 工作流**」：长上下文与可编辑画布如何改变交付形态 | 研究「**默认分发 + 混合检索**」：AI 如何寄生在已有超级应用上放大采纳 |

## 二、关键维度深度对比

### 2.1 从 chat 到 task：任务完成度

三款产品都在回答同一个 PM 命题：**用户要的是「聊完」还是「做完」**。

- **ChatGPT** 的路径是 **chat-first，向 agent 演进**：对话仍是主界面，但通过函数调用、GPT、项目上下文、逐步增强的自动化，把「多步任务」收拢到同一会话里。战略含义是：**用「会话」统一一切**，任务完成度取决于工具链是否接得够深；在 OpenAI 栈外，最后一公里仍常落在用户自己拼接工具上。

- **Claude** 通过 **Artifacts 等「对话外的结构化载体」** 显式提升任务完成度：产出不再是纯气泡，而是可编辑、可反复优化的工件。战略含义是：**把「可交付物」产品化**，更接近文档工具的思维，适合写作、代码块、页面原型等「要留下来改」的任务。

- **Gemini** 的路径是 **把任务锚定在 Workspace 与 Search**：生成直接发生在文档、表格或检索结果旁，任务完成度由 **Google 产品是否覆盖该工作流** 决定。战略含义是：**不追求独立 AI 应用打败所有场景，而追求在超级应用内闭环**。

**PM takeaway**：任务完成度不只等于「模型更强」，而等于 **上下文在哪里结束、编辑在哪里发生、谁对结果负责**——三款分别押注「会话中心」「可编辑工件」「办公与搜索宿主」。

### 2.2 产出可编辑性与可验证性

| 产品 | 可编辑性 | 可验证性 |
|------|----------|----------|
| **ChatGPT** | 以 **复制粘贴** 为主，辅以 Canvas 等能力；编辑多在第三方工具完成 | 用户在外部工具中核对来源与格式；对话内「真源」弱，版本感依赖聊天记录 |
| **Claude** | **Artifacts** 支持就地编辑与迭代，减少「导出再改」摩擦 | 仍须在业务系统或文档中做最终校验，但界面内迭代路径更短 |
| **Gemini** | **直接进入 Docs/Sheets** 等，编辑与协作在熟悉环境中完成 | 可验证性与 **链接分享、评论、版本历史** 同源，组织内信任链条相对清晰 |

**PM takeaway**：B 端与高 stakes 场景里，**可验证性 ≈ 与组织真源（文档、表格、工单）的距离**；C 端则更易接受「气泡即终点」。

### 2.3 生态与分发

- **ChatGPT**：**GPT Store** 扩展长尾场景；**API** 成为事实标准之一；与 **Microsoft** 的协同让「通用助手」能力渗入 Office 叙事，形成「独立产品 + 云巨头渠道」双轮。

- **Claude**：**API + 企业合同** 是增长主引擎；独立 App 服务专业用户，但大众默认选项仍弱于前两者。护城河更偏 **模型信任与集成深度**，而非消费者商店规模。

- **Gemini**：**Google Search** 提供全球最大规模之一的意图入口；**Workspace** 锁定知识工作与协作。**混合检索 + 账号** 使「不用安装新习惯」成为核心分发命题。

**PM takeaway**：分发策略本质是 **「新建习惯」vs「寄生旧习惯」**——OpenAI 偏前者，Google 偏后者，Anthropic 偏 B 端 API 与口碑穿透。

### 2.4 商业化路径

- **ChatGPT**：**Freemium 拉新 + 订阅变现 + API 与企业**；GPT 生态尝试拓宽付费场景。逻辑是 **最大用户基数 × 多层变现**。

- **Claude**：**API-first 与订阅并重**；企业愿意为可控、可集成能力付溢价。逻辑是 **高意愿专业用户与 B 端 ARPU**。

- **Gemini**：**捆绑 Google One / Workspace**，AI 作为套餐增值而非孤立 SKU。逻辑是 **提高整体订阅黏性与云生态价值**，而非单独证明「聊天机器人」的付费率。

**PM takeaway**：同一品类下，**Unit economics 的叙事可以完全不同**——卖「AI 应用」、卖「API 能力」、卖「套件增值」对应不同的路线图与成功指标。

## 三、用户选择决策树

以下为简化决策逻辑，便于做用户细分与竞品话术设计（非唯一答案，需结合地区可用性与合规）。

- **若你需要最强默认心智与最大插件/开发者生态，且接受以对话为主的工作流** → 优先考虑 **ChatGPT**。

- **若你主要处理长文档、严肃写作、分析报告，且重视对话内可编辑产出与「专业可靠」叙事** → 优先考虑 **Claude**。

- **若你工作流已在 **Google 搜索 + Gmail + Drive/Docs**，且希望少复制粘贴、强依赖实时信息与多模态** → 优先考虑 **Gemini**。

- **若你是企业技术负责人，要深度嵌入自有产品（客服、内部工具、RAG）** → 在 **ChatGPT API** 与 **Claude API** 间按合规、延迟、成本与效果评测二选一或双 vendor；**Gemini** 若在 GCP/Workspace 已统一，常作为同栈选项。

- **若你极度在意「结果留在哪里、谁能否认」** → **Gemini（Workspace）** 或 **Claude（Artifacts）** 通常优于纯气泡体验；若组织已标准在 Microsoft 365，则实际落地常回到 **Microsoft 生态内的 Copilot 类体验**，与 ChatGPT 形成「表内竞争」。

- **若你只是轻度问答、不想付费** → 三者免费层均可试；**分发上** 已装 Google 或常用搜索的用户更易留在 **Gemini**，已养成 Chat 习惯的用户更易留在 **ChatGPT**。

## 四、品类趋势与预判

1. **从「单轮聪明」到「任务闭环」**  
   用户评估标准从「回答是否漂亮」转向「是否少步完成、可复核、可协作」。Artifacts、Workspace 嵌入、Agent 编排都是同一趋势的不同解法。

2. **「通用」被解构为多层：模型层 / 工具层 / 宿主应用层**  
   纯聊天 UI 差异化收窄，竞争上移到 **默认入口（搜索、邮箱、文档）** 与 **企业数据管线**。通用助手作为独立品类的边界会变模糊。

3. **检索增强与权限边界成为产品主战场**  
   谁能安全地接企业数据、个人文件、实时网页，并保持引用可解释，谁在高价值场景占优。Gemini 与 Google 数据栈、Microsoft + OpenAI 联盟、Anthropic 的企业 API 各据一侧。

4. **商业模式收敛为三种叙事：消费订阅、API/平台税、套件捆绑**  
   PM 需在早期选定主叙事，否则会出现指标打架（DAU vs API 毛利 vs Workspace 续费）。

## 五、PM 启示总结

1. **品类定义权不等于终局**：ChatGPT 定义了「对话式通用助手」的心智，但高价值场景可能被 **搜索、文档、代码编辑器** 等宿主「截胡」；独立 App 必须回答「为何不从别处分发」。

2. **差异化要打在「交付形态」与「信任假设」上**：长上下文、Artifacts、进 Docs 都是 **降低从生成到采用摩擦** 的设计，比单纯榜单上的模型分数更接近产品战略。

3. **分发策略决定产品形态**：寄生超级应用（Google）vs 自建目的地（OpenAI）vs API 穿透（Anthropic）对应不同的路线图、组织能力与北极星指标。

4. **商业化要与宿主一致**：API-first、Freemium、捆绑增值三套逻辑对路线图、合规、定价页面的要求完全不同；混用易导致内部优先级撕裂。

5. **研究本品类时，建议并排观察「微软 Copilot」等表内竞品**：许多企业用户的真实二选一并非 ChatGPT vs Claude，而是 **独立助手 vs 办公套件内嵌助手**，矩阵分析需把「宿主」纳入同一框架。
