# Claude 系列：多入口与适用场景总览

**用途**：快速回答「Chat / 桌面 / CLI / 插件」分别适合干什么；与单品深度稿互补。  
**最后更新**：2026-03-30

---

## 1. 一张表看懂

| 入口形态 | 典型产品名 | 你在哪儿用 | **最适合的场景** | **不太适合的场景** |
|----------|------------|------------|------------------|-------------------|
| **网页对话（Chat）** | Claude.ai（浏览器） | 浏览器 | 通用问答、长文档/多附件理解与摘要、多轮写作与改写、**Artifacts** 产出可编辑文档或代码片段、轻量代码讨论（不直接改仓库） | 需要**直接改本地仓库文件**、跑构建/测试命令、操作整棵目录树 |
| **桌面应用** | Claude Desktop | 本机安装的 App | 更稳定的「常驻助手」体验；承载 **Cowork** 等需**本地文件/工作区**的能力；减少浏览器标签干扰（具体功能以当前版本为准） | 仅想随手打开网页问一句时，安装成本略高 |
| **终端 CLI** | Claude Code（`claude`） | 终端 / CI | **以代码仓库为边界**的开发：跨文件改代码、跑 `git`/包管理器/测试、脚本化与非交互任务、与现有命令行工作流同屏 | 非工程向的「写周报 PPT」、不适合把仓库当上下文的任务 |
| **IDE 插件 / 扩展** | Claude Code for VS Code、JetBrains 等 | 编辑器内 | **不离开 IDE** 完成实现与重构：选中即上下文、diff 在编辑器内审阅、诊断信息自动带入、多文件编辑与终端命令仍受你批准 | 不写代码的日子；或强依赖「纯聊天排版」的文稿工作（更偏 claude.ai） |
| **其他工程向触点** | Claude Code on Web、Slack 等 | 浏览器 / 团队工具 | 团队已在 Slack 协作、或需在 Web 上触发与代码库相关的代理任务（权限与可用性以组织配置为准） | 与本地离线/低延迟强绑定的重度调试（往往仍回 IDE/CLI） |
| **知识工作代理（子能力）** | **Claude Cowork** | **桌面应用内** | **非开发为主**：整理本地文件夹、从多份合同/PDF 抽取与汇总、重复性文档合成——**委托多步、交付文档/表格类结果** | 以 Git 与编译为中心的软件工程（更偏 Claude Code） |
| **开发者 API** | Claude API / Console | 你自己的产品里 | 把 Claude 接进 App、客服、内部工具；批处理、服务端调用 | 个人日常「聊天」体验；需直接用官方聊天 UI 时 |

说明：**「插件」在官方叙事里主要指 Claude Code 的 IDE 扩展**（VS Code、JetBrains 等），与「打开 claude.ai 聊天」是两条产品线；不要混成一个「Claude 插件」。

## 2. 按任务选型（我该开哪个？）

- **读一份 100 页的 PDF、写摘要、对照问答** → **网页 Chat（claude.ai）**（长上下文 + 附件 + 必要时 Artifacts）。
- **写一篇长文、反复改语气与结构，产出可复制的成品** → **网页 Chat**，善用 **Artifacts**。
- **在真实项目里改 10 个文件并跑 `npm test`** → **CLI 或 IDE 插件（Claude Code）**，不要用纯聊天窗口手工粘贴。
- **每天写代码，希望 AI 在编辑器里出 diff、点确认再应用** → **IDE 插件**。
- **习惯终端、要可脚本化、要和 CI 对齐** → **CLI**。
- **整理桌面上的项目文件夹、从一堆合同里扒表格、做汇报初稿（不主要是写代码）** → **桌面应用 + Cowork**（若你的账号与版本支持）。
- **给自家网站做一个聊天机器人后端** → **API / Console**，不是 Chat 界面。

---

## 3. 产品边界（PM 一句话）

- **Chat（claude.ai）**：对话与**可交付草稿**为中心，上下文主要是**你上传的内容 + 会话**，不默认拥有「整个磁盘/整个 repo」的写权限。
- **Claude Code（CLI / IDE / Web / Slack）**：上下文是**工作区/仓库**，动作是**工程操作**（读写文件、跑命令），心智是**编码代理**。
- **Desktop**：**宿主应用**——既改善聊天体验，又是 **Cowork** 等「本地计算机工作」能力的载体。
- **Cowork**：**Code 的技术路线在知识工作场景的包装**——文件夹与文档，而不是 Git 与编译。
