# 海外主流支付机构概览 — Stripe / PayPal / Visa 等

**品类**：跨境支付生态 · 卡组网络 · 收单与支付服务商（PSP）· **最后更新**：2026-03-31

---

## 一、摘要：先分清「层级」

海外支付链条里，**Stripe、PayPal 与 Visa 并非同一类机构**：

| 层级 | 典型角色 | 对商户的体感 |
|------|-----------|----------------|
| **卡组网络（Card scheme）** | **Visa**、**Mastercard**、（美国境内常见 **American Express** 双角色） | 制定规则、清算与品牌；**不**直接给每个网店开「Stripe 式」后台 |
| **收单机构（Acquirer）** | 银行持牌收单、或大型 PSP 下设收单实体 | 把商户接进卡组，承担风控与结算关系 |
| **支付服务商 / 网关（PSP、Payfac）** | **Stripe**、**Adyen**、**PayPal**（部分场景）、Checkout.com 等 | 开发者/商户集成的**主入口**：API、收银台、订阅、对账 |
| **数字钱包与消费者品牌** | **PayPal**、**Venmo**、Apple Pay、Google Pay | 结账时用户选的支付方式；同时 PayPal 也做 **商户侧** 处理 |

研究或选型时，应问：**你要对接的是「网络规则 + 覆盖率」还是「一体化集成 + 产品迭代速度」**——前者看 Visa/Mastercard 与收单行，后者看 Stripe/Adyen/PayPal 等平台。

## 二、核心机构卡片（简要）

### 1. Visa（维萨）

- **官网**：[visa.com](https://www.visa.com/) · **公司/产品**：[corporate.visa.com — Products](https://corporate.visa.com/en/products.html) · **开发者**：[developer.visa.com](https://developer.visa.com/)
- **一句话**：全球主流 **开放式银行卡网络** 之一，连接发卡行、收单机构与商户，提供规则、清算、风控与数据类产品。
- **目标用户**：发卡机构、收单机构、大型商户与科技公司（通过 **Visa Acceptance Platform** 等）、政府与企业支付项目。
- **和 Stripe 的关系**：商户通过 **Stripe/Adyen 等 PSP** 接卡时，底层授权/清算往往仍走 **Visa 或 Mastercard 网络**（在具体路由与费率链上分工不同）。
- **差异化**：网络覆盖与标准制定；**Visa Developer** 面向 B 端集成（API、令牌化、数据服务）。商户日常不「直接签 Visa」接线上卡收单，多通过收单/PSP。

### 2. Mastercard（万事达卡）

- **官网**：[mastercard.com](https://www.mastercard.com/) · **新闻与能力示例**：[Newsroom](https://www.mastercard.com/news/)
- **一句话**：与 Visa 同类的 **全球支付网络与技术公司**，在数字商务、令牌化、收单侧产品（如面向商户的开放平台能力）上持续投入。
- **备注**：公开材料中亦有 **代理式商业（agentic commerce）**、**Merchant Cloud** 等叙事，体现其从「纯网络」向 **平台化服务** 延伸；PM 可关注其与 **PSP / 商户** 的分工边界。

### 3. Stripe

- **官网**：[stripe.com](https://stripe.com/) · **文档**：[stripe.com/docs](https://stripe.com/docs/) · **公司动态**：[Annual updates / Newsroom](https://stripe.com/newsroom)（具体路径以官网为准）
- **一句话**：面向互联网企业的 **支付与金融基础设施**——线上收单、Billing/订阅、Connect 分账、发行（Issuing）、税务、 increasingly 稳定币/资金移动等。
- **目标用户**：初创到大型互联网公司、平台与市场、SaaS、全球化商户。
- **差异化**：**开发者体验**与产品面宽（「全栈」支付）；与 **卡组** 的关系是 **在其之上** 做集成与增值，而非替代 Visa/Mastercard。
- **数据口径**：体量与国家覆盖等以 **Stripe 官方报告/新闻稿** 为准；引用时需核对最新年度材料。

### 4. PayPal

- **商户与产品**：[PayPal — Merchant / Business](https://www.paypal.com/us/webapps/mpp/merchant) · **企业**：[Enterprise](https://www.paypal.com/us/enterprise/platform) · **开发者**：[developer.paypal.com](https://developer.paypal.com/)
- **一句话**：**C 端钱包品牌 + B 端收单与商务解决方案**，覆盖网店、账单、POS、分期、全球打款等。
- **目标用户**：中小企业到大型企业；强依赖「买家愿用 PayPal 结账」的商户。
- **差异化**：**存量账户网络**（登录即付、信任与争议流程）；费率与产品线分区复杂，需按官网 **Pricing** 与区域条款核对。
- **对标**：与 Stripe/Adyen **部分重叠**（都能收卡），又多一层 **自有钱包** 轨；常和 **Braintree**（PayPal 旗下）等在技术集成上协同（以官方当前文档为准）。

### 5. Adyen

- **官网**：[adyen.com](https://www.adyen.com/) · **文档**：[docs.adyen.com](https://docs.adyen.com/)
- **一句话**：偏 **大型企业** 的 **统一支付与金融科技平台**——多渠道（线上、门店）、多币种、本地支付方式、风控与部分牌照区域 **自有收单** 能力。
- **目标用户**：跨国零售、电商、出行、数字内容、平台型公司。
- **差异化**：**单平台、单 API 叙事** + 强 **企业级运营与牌照布局**；常与 **Stripe** 在「全球化 enterprise」标案中对标。

### 6. 其他常见「主流」补充（便于扫盲）

| 机构 | 备注 |
|------|------|
| **Square（Block）** | 北美 SMB、线下 POS + 线上；与 Stripe 在中小商户侧有重叠。 |
| **American Express** | 在美国等地常 **自营发卡 + 收单** 链条；与 Visa/MC 网络模型不完全相同。 |
| **Checkout.com、Worldpay（FIS）、Nuvei** | 全球化或区域强势 **PSP/收单**，常出现在大厂 RFP 名单中。 |

## 三、对比矩阵（PM 速查）

| 维度 | Visa | Mastercard | Stripe | PayPal | Adyen |
|------|------|------------|--------|--------|-------|
| **本质** | 卡组网络 | 卡组网络 | PSP / 基础设施 | 钱包 + 商户服务 | 企业向 PSP / 平台 |
| **商户典型对接方式** | 经收单/PSP；大企业可深度接网络产品 | 同左 | 直接集成 API / Checkout | 商务账户 + API / 标准结账 | 企业合同 + API |
| **核心卖点** | 全球受理、规则、清算、数据与安全标准 | 同左；平台化产品增加 | DX、产品线宽、迭代快 | 用户池、品牌信任、多维商务产品 | 统一平台、跨国企业、线上线下一体 |
| **主要收入逻辑（简）** | 网络费、数据与增值服务 | 同左 | 处理费 + 软件/增值 | 交易费 + 金融产品等 | 处理费 + 平台费（以合同为准） |
| **与 AI / Agent 商业** | 网络层叙事（安全、令牌、代理式支付实验） | 明确推动 agentic payments 等 | Billing/编排与自动化叙事强 | 视产品线 | 企业自动化与数据 |

## 四、为什么「能接很多支付方式」

1. **卡组**：一张「Visa」背后已是全球银行发行的大量卡产品，商户侧通过 **一次 PSP 集成** 可触达多卡组、多币种（具体仍依赖 PSP 开通）。
2. **PSP 聚合**：Stripe/Adyen 等将 **iDEAL、Sofort、PIX、GrabPay** 等本地方式 **统一抽象** 为一个集成面。
3. **钱包轨**：Apple Pay / Google Pay / PayPal 再走各自令牌化或重定向流程，PSP 侧常提供 **一站式开关**。

## 五、风险与待验证

- **费率、拒付、冻结与合规**：强烈依赖 **国家、行业、MCC、风控评分**；公开文章与真实合同可能有偏差，`to verify` 以 **PSP 销售/合规** 为准。
- **角色混用**：同一品牌（如 PayPal）既有 **钱包** 又有 **收单**；讨论「有没有牌照」时要 **具体到法律实体与产品线**。
- **数据引用**：交易量、市占、国家数等营销数字更新快，**写报告时钉死到具体文档与日期**。

## 六、支付 PM 启示与核心关注点

- **先画_payment triangle_**：**Issuer（发卡）— Network（Visa/MC）— Acquirer/PSP（Stripe 等）— Merchant**，再说「我们和 Stripe 竞合」。
- **差异化不是「我们又做了一个 Visa」**：大部分是 **在台上做体验、编排与软件**；网络层是 **基础设施 + 监管护城河**。
- **海外选型**：同时评估 **卡组覆盖率、本地支付方式、订阅/Billing、Connect/分账、提现周期、争议与欺诈工具、SLA**。

## 七、Product Q&A（三类典型角色）

### Q&A — **卡组网络（以 Visa / Mastercard 为原型）**

| 问题 | 回答 |
|------|------|
| 第一次为什么关注？ | 要理解卡支付 **规则、成本结构与全球受理** 的上限。 |
| 重复价值？ | 新产品（代币、B2B、数据服务）影响所有下游商户体验与成本。 |
| 旧工作流痛点？ | 分散的银行与标准不统一；网络提供 **互操作性**。 |
| 护城河？ | 双边网络、品牌信任、合规与风控标准、规模。 |
| 聊天 vs 任务？ | **基础设施任务**（清算、认证、数据）。 |
| AI？ | 多在 **欺诈检测、授权优化、新兴代理式支付** 等场景，非 C 端聊天产品。 |
| 产出可验证性？ | **强**——交易数据、对账、争议规则可审计。 |
| 变现？ | **网络费与增值服务**，非按 LLM token。 |

### Q&A — **PSP / 基础设施（以 Stripe / Adyen 为原型）**

| 问题 | 回答 |
|------|------|
| 第一次为什么来？ | 快速上线跨境收款、订阅与分账，减少自建网关。 |
| 第二次为什么回来？ | 业务扩张到新国家/新渠道；深度用 Billing、Connect、Issuing。 |
| 痛点？ | 多边对接、PCI、合规、对账与失败路由。 |
| 护城河？ | 开发者粘性、产品矩阵、风控与成功率数据飞轮、企业切换成本。 |
| 聊天 vs 任务？ | **集成与运营任务** 工具。 |
| AI？ | 作为 **授权、风控、客服、对账** 的嵌入能力递增。 |
| 产出？ | 日志、报表、可编程资金流；**可验证、可集成**。 |
| 变现？ | **处理费 + 软件层**；规模越大议价与定制化越强。 |

### Q&A — **钱包 + 商户平台（以 PayPal 为原型）**

| 问题 | 回答 |
|------|------|
| 第一次为什么来？ | 买家要 **PayPal 结账**；或需要一体化中小企业方案。 |
| 第二次为什么回来？ | 账户、争议、多产品捆绑（打款、贷、POS）。 |
| 痛点？ | 多支付方式与跨国信任、购物车放弃率。 |
| 护城河？ | **消费者账户网络 + 品牌**；商户侧工具体量。 |
| 聊天 vs 任务？ | **支付完成任务**；客服纠纷链长。 |
| AI？ | 多在 **风险、自动化与客户支持**，非核心卖点叙事主体。 |
| 产出？ | 交易与余额记录；争议结果可跟踪。 |
| 变现？ | **交易抽成** + 金融服务。 |
